# 0.4.0 额度循环验证

验证日期：2026-10-26 至 2026-10-27。

本功能将循环规则与一次性队列分开保存。每轮生成带稳定请求编号的普通队列任务，沿用原有模型、服务商、对话权限、发送回执与结果核对流程。启用规则才会持续重复发送；开发或升级不会自动建立真实规则。

## 已验证

- 391 项自动测试通过，0 失败、0 跳过；其中循环状态机 40 项。
- 初次实际使用量为零才允许满额触发；部分额度先等待。界面取整、微小用量、周额度和多额度桶不会被误当作一个全新 5 小时窗口。
- 首次缺少刷新时间时仅触发一次，再等待绑定；同轮刷新时间微调、重启、重复请求均不会生成第二条。
- 部分额度跨过已记录边界后，若服务端明确返回新窗口，即使其他请求已经消耗了本轮的一点额度，也能识别刷新。
- 对话忙、跨窗延迟或错过多轮时不积压、不补发历史窗口；子任务结果不明时停止并要求核对。
- 覆盖规则写入前后、队列写入前后及结果确认前后的恢复点。规则与子任务创建、恢复写入失败时，不留下可派发的未提交状态。
- 覆盖同一时间的暂停、删除、恢复操作；后来的暂停不会被较早的恢复覆盖。已派发工作不被强行中断。
- 真实浏览器操作验证三种发送方式、默认短消息、创建、暂停、恢复、关联任务和删除确认取消；窄窗口与确认弹窗未出现横向溢出。
- 隔离服务使用生产循环和队列模块，模拟额度与模型：部分额度初始发送数为零，刷新后为一，同轮多次检查和重新加载仍为一；下一窗口变为二；暂停跨窗口仍为二；模拟结果不明后停止，不在后续窗口重发。
- 本机安装后新会话发现 6 个工具，循环创建与操作 schema 已更新。稳定副本及缓存与源码一致，私有运行时校验通过；原有 10 条真实任务及设置的 SHA-256 保持不变。

## 验证边界

没有向真实对话发送测试消息，也没有启用任何真实循环。模拟额度前移验证状态机，不等于经过了真实的 5 小时计费周期。

本次本机账号接口只返回一个 10080 分钟的周窗口，未返回 300 分钟窗口。因此无法在该账号上确认真实 5 小时刷新与消息用量。界面会提示缺少窗口，规则只保存并等待，不把周额度、未知信息或固定 5 小时间隔当作发送授权。

本功能不能改变服务端限额，也不能保证一条短消息恰好消耗 1% 或必定重置平台计时。窗口边界以服务端实际返回的数据为准。

Windows x64 离线包完成文件、架构与运行时哈希验证；最终包还通过了空用户目录、系统 PATH 无 Node、禁止下载仍可用、损坏运行时拒绝、真实 Codex 新会话六工具发现和删除原解压目录后的复验。隔离目录未继承登录、对话、项目或任务。ARM64 完成静态包校验，没有 ARM64 实机执行验证。本次没有重复进行标准 Windows 账号的完整桌面登录测试。
