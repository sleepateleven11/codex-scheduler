# 0.3.4 Windows 安装验证

验证日期：2026-10-24。主机：Windows 11 专业版，64 位，系统版本 10.0.26200。以下是本次实际结果，不代表所有 Windows 版本或组织策略都经过测试。

## 修复

- 全新安装没有本插件缓存时，不再先查询旧连接进程。
- 系统不允许查询进程时，保留全部进程，由 Codex 判断安装结果；无法停止已确认归属本插件的连接时仍然报错。
- 桌面或开始菜单入口创建失败时，单独说明入口问题，不把已安装并通过六工具验证的插件误报为安装失败。
- 后台计划任务查询区分“任务不存在”和权限、服务错误；卸载不会把查询失败误报为已清理。

## 真实普通用户验证

测试使用经用户授权新建的临时本地标准账号。实际进程属于新的非管理员 SID，属于 Users、不属于 Administrators；令牌未提权，完整性级别为 Medium。加载真实用户配置文件和 HKCU，使用该账号自己的桌面和开始菜单。没有通过修改 USERPROFILE 来冒充普通用户，也没有继承原账号的 Codex 登录或聊天数据。

测试任务仅为已取消任务和 2099 年的未来任务。没有发送模型消息，也没有登录原用户的 Codex。

测试结束后，独立进程核查确认临时账号、用户配置文件、注册项、加载的用户注册表、私有测试目录均已清理，关联任务与进程为零。测试脚本最初删除配置文件时返回错误 87，修正原生空参数传递后完成清理，原失败记录保留；这项测试环境清理与插件正式卸载分别核验。

## 后台验证边界

普通账号成功自行注册、读取和删除了属于自己的 Interactive / Limited 后台计划任务。但该临时账号通过隔离登录运行测试，没有完整登录 Windows 桌面；系统接受启动请求后，任务仍为 Ready，结果为 `0x41303`（尚未运行）。因此，**本次未验证普通用户完整桌面登录后的后台脱离和持续运行**。

上表的普通用户服务测试是直接启动服务进程，验证普通权限下的运行、页面、认证与停止，不替代计划任务的持续运行验证。当前已登录主账号的正式后台启动及连接自检通过，升级后原有 10 条任务与设置保持不变。

## 其他验证

- 335 项自动测试通过，0 失败、0 跳过；语法与插件结构检查通过。
- 最终 x64 离线包经过独立隔离验收：Windows PowerShell 5.1、真实 CMD、PATH 无 Node、忽略旧 Node、阻止预加载污染、禁止下载仍可安装、损坏运行时执行前拒绝。删除解压目录后，新进程仍发现 6 个工具。
- 轻量源码包的生产下载器实际联网下载官方 Node.js 24.22.1，校验固定 SHA-256 和许可后执行成功。
- x64、ARM64 官方运行时的 PE 结构、二进制及许可哈希通过；静态直接导入均为 Windows 系统 DLL，无延迟导入或额外 VC++ 运行库导入。此检查不代表所有动态加载分支均已运行。
- ARM64 尚无硬件执行验证；没有第二台实体电脑验证。组织策略禁用本地脚本或计划任务时，不修改这些策略。
