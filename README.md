# Codex Scheduler

Codex 桌面本地插件，当前版本 0.3.2。选择项目、已有对话、GPT 模型、思考强度和发送时间；到时通过 Codex 自带的桌面工具服务继续原对话。额度不足时保留任务，等待恢复后执行。

下载安装包：[GitHub Releases](https://github.com/sleepateleven11/codex-scheduler/releases/latest)。请下载 Release 中的 `codex-scheduler-0.3.2.zip`，完整解压后运行“安装插件.cmd”。

## 发给别人或换电脑安装

可以分享 `codex-scheduler-0.3.2.zip`。接收者使用自己的 Codex、ChatGPT 登录、项目和对话，不需要你的账号、API Key 或安装路径。目前分发版支持 Windows，需要 Node.js 22 或更高版本。

1. 在新电脑安装并启动 Codex 桌面，登录自己的 ChatGPT 账号，添加本地项目并建立一个使用 OpenAI 服务商的对话。
2. 安装 Node.js 22 或更高版本；把 ZIP **全部解压缩**后，双击文件夹里的 **“安装插件.cmd”**。如果提示旧版 Node 或缺少 Codex，先完成提示的安装步骤再运行。
3. 首次在 Codex 的一个本地对话中让时序插件 **“打开定时任务管理器”**，以登记真实的桌面发送连接。之后可以直接双击桌面或开始菜单的 **“时序任务管理器”**。
4. 在管理器展开 **“首次设置与连接自检”**，点击 **“重新检测”**。检查包含运行环境、Codex、登录、服务商、桌面发送连接、本机项目和 GPT 模型；全部通过后再选择自己的项目、已有对话并创建任务。自检只读状态，不发送测试消息。

安装器把完整程序复制到当前用户的稳定安装目录，并按这台电脑重新生成启动配置；安装成功后可移动或删除原解压目录。分发包不包含个人任务、聊天记录、账号凭据或桌面连接信息。更新和重装保留本机队列；**将 ZIP 发给其他人不会迁移你的任务或登录状态**。换电脑后的旧任务涉及原电脑的项目路径和对话 ID，需要在新电脑重新选择目标并安排。

## GPT 与服务商校验

本版本仅支持 **OpenAI / ChatGPT 订阅通道**。对话列表与详情显示实际服务商。模型名与服务商是两项不同设置：一个绑定 DeepSeek 的旧对话，即使选择 GPT，也不会自动变成 OpenAI 对话。

创建任务、排队执行和实际发送前都会核验目标对话的真实服务商、项目配置、登录方式与 GPT 模型。DeepSeek、未知服务商、自定义外部 OpenAI 地址和 API 认证覆盖会被阻止，并显示处理说明。请在 Codex 中使用 OpenAI 对话后刷新；如果旧对话无法切换服务商，选择或创建一个 OpenAI 对话。本插件不会擅自修改全局配置或迁移聊天，也不会反复发送产生 401 的旧消息。

## 安装与打开

需要 Windows、已安装并登录的 Codex 桌面，以及 Node.js 22 或更高版本。下载 ZIP 后，先右键选择 **“全部解压缩”**，打开解压后的完整文件夹，再双击 **“安装插件.cmd”**。不要在压缩包窗口中直接运行安装或卸载入口；Windows 可能只临时提取入口文件，导致所需的 `scripts`、`src` 和 `package.json` 不在同一目录。

也可以在完整解压后的目录运行：

```powershell
npm run install:plugin
```

安装器注册本插件的本地来源和插件配置，自动查找 Codex 与 Node.js，保留其他插件和设置。安装成功后，桌面和开始菜单会出现 **“时序任务管理器”**，双击即可在默认浏览器打开，不需要向 GPT 发送消息。快捷方式会获取当前有效地址，不保存端口或访问令牌。

也可继续在 Codex 中说 **“打开定时任务管理器”**。插件提供标准 MCP Apps 全局和对话面板入口；宿主加载并展示入口后，可以点击“时序任务管理器”，再打开本机管理器。如果当前对话尚未加载新版插件，重新加载插件或打开一个 Codex 对话。入口展示位置由宿主决定，桌面和开始菜单入口始终可独立使用。

命令方式 `npm run open` 会直接打开浏览器；自动化需要仅获取当前地址时使用 `npm run open -- --url`，不要分享带访问令牌的地址。

也可以先检查安装计划，不修改 Codex 设置：

```powershell
npm run install:plugin -- --dry-run
```

此版本采用本地源安装。安装器自动建立稳定来源，Codex 从插件缓存运行代码和管理页面。更新或卸载时可以重新解压同一个分发包使用对应入口，不依赖原解压目录的位置。更换电脑时，在新电脑上重新运行安装器并完成首次自检。

更新包解压到新目录时，直接在新目录运行安装器即可。安装器先验证旧来源属于 `codex-scheduler@local-scheduler` 后迁移。旧解压目录已删除时，还须以已启用的专用插件注册和对应版本缓存验证身份；无法确认、身份不符或同一来源包含其他插件时，会保留原注册并报错。不会覆盖无关的同名来源。

重新安装或升级前会停止旧后台继续派发任务。如果当前一轮仍在执行，安装器会保留现有插件并提示等这一轮结束后重新运行；不会中断当前轮来覆盖缓存。

## 0.3.2 删除任务

每张任务卡片提供 **“删除”**，确认后从本地队列和历史记录移除，无法从管理器恢复。等待或暂停的任务删除后不再发送；已完成、失败、取消的记录也可清理。执行中或正在派发的任务不能删除，请等待执行结束。

删除只处理本机任务记录，不删除 Codex 对话或已经发出的消息。“需要核对”的任务可能已经发送，删除后不会撤回消息，也不再跟踪其结果；请先核对原对话。删除当前正在编辑的任务会保留表单内容为新草稿，只有再次创建才会发送。

删除写入失败时会保留记录并暂停调度；等待发送的任务会尽可能保存为暂停状态。处理磁盘空间或权限问题后，再次点击删除重试。

此版本也增加了 Windows 安装目录短暂占用时的有界重试；始终核验目标副本，不覆盖其他来源或任务数据。

## 0.3.1 界面改进

管理器统一了字号、配色、间距和组件状态。创建表单按目标、执行方式、消息内容分组；桌面任务区独立滚动，窄窗口提供任务区域快捷跳转。长结果可展开查看，不挤压操作按钮；搜索和刷新对话不会静默丢失当前目标，读取失败与空数据有明确区分。

创建、检测和任务操作会显示加载状态，禁用控件与加载控件采用不同反馈。重试结果不明的消息时，使用支持键盘与 Escape 的确认弹窗。任务数据、服务商校验和发送逻辑保持原有规则。

## 日常使用

1. 选择项目和已有对话，再选择本账号当前可用的模型与思考强度。同名对话以北京时间的更新时间和唯一编号区分；选中后可查看创建时间、完整编号与内容预览，也能按日期、编号和内容搜索。上次的有效选择会保存在本机，后台重启后仍可恢复；消息草稿不会存入偏好设置。
2. 设置发送时间，或勾选 **“额度可用时立即发送”**，填写消息后保存。勾选时无需设置时间，保存后每 30 秒读取一次最新额度；检测到额度可用便自动发送，当前已经可用时会立即加入发送队列。仅勾选不会创建或发送任务；此选项不影响其他任务，下次新建默认仍按时间发送。检测在后台进行，关闭页面后仍会继续。
3. 等待中的任务可编辑、暂停、恢复或取消；编辑保留原任务 ID，暂停任务保存修改后仍保持暂停。已经提交、执行或需要核对的任务不能编辑。
4. “复制”会填入新草稿，只有再次点击“创建定时任务”才会创建新任务。历史消息不会因为复制而自动重发。
5. 队列区分已提交等待开始、执行中、已完成，显示等待额度或对话的再次检查倒计时。页面打开期间，完成、失败或需要核对会出现可关闭的站内提醒。
6. 需要清理队列或历史时，点击任务卡片的“删除”并核对确认说明；“取消”仅停止排队并保留记录，“删除”会移除记录。

同一对话正在运行时任务会等待。额度不足时进入等待额度状态，并参考账号返回的恢复时间继续尝试。不会自动更换模型，不会调用额外付费 API，也不会增加或绕过订阅额度。

桌面返回“已接收”只表示消息已提交，插件会继续核对原对话的实际执行记录，确认该轮结束后才标记完成。如果提交后的连接中断或结果无法确认，任务会保留并提示核对，不会自动重发同一条消息。

后台与管理页面分开运行。首次打开时，插件会创建一个仅限当前用户、按需启动的 Windows 计划任务，用它启动隐藏后台；关闭管理页面或当前 Codex 对话后，后台仍能继续处理队列。**Codex 桌面应用必须保持运行**，发送需要它自带的工具服务。这个计划任务没有定时、登录或开机触发器，只在打开插件时按需运行。

当前 Windows 用户需要保持登录，电脑开机且未休眠；网络或登录失败时会保留任务及错误原因。任务保存在 `%LOCALAPPDATA%\CodexScheduler`。Codex 初始化本插件的 MCP 服务时，会自动登记宿主提供的真实桌面连接，无需请求模型生成回复。退出或重启 Codex 后，重新加载插件可刷新该连接；双击桌面入口会启动后台、检查连接并打开管理器。

管理器分别显示后台状态与 Codex 发送服务状态。连接暂时中断时，可点击 **“重新连接”**，恢复成功后等待中的任务继续排队；这只检查连接，不重发已提交的消息。如果宿主尚未加载插件、未提供新的连接信息，页面会保留具体原因并提示重新加载，普通快捷方式不会伪造宿主连接。电脑重启后的后台仍按需启动，不增加开机触发器。如果 Windows 不允许创建后台计划任务，插件会明确报错。

0.2.3 修复 Codex 重启后旧发送连接失效的问题：宿主提供新的本机连接时，即使全局插件初始化没有附带对话编号，也会复用已经验证保存的来源对话刷新连接；首次连接仍须由宿主提供真实来源。管理器的重新连接只做只读检查，不重发已提交消息。

0.2.1 修复了 Windows 卸载后重装的缓存占用问题：插件工具使用稳定数据目录作为工作目录，安装和卸载会先验证并关闭本插件连接，再更新缓存。安装器在 Codex 用户目录的 `codex-scheduler-install.json` 中只记录任务数据的真实路径，确保从 Codex 外部双击安装、卸载时，也能找到同一个后台与队列。该路径记录随任务数据一起保留，不含账号凭证。

如需卸载，在完整解压的插件文件夹中双击 **“卸载插件.cmd”**，也可在该目录运行：

```powershell
npm run uninstall:plugin
```

卸载会先停止继续派发任务。如果当前一轮仍在执行，会保留插件和启动器并提示等这一轮结束后重新卸载。卸载完成后，会删除本插件的按需启动计划任务及经归属检查的桌面、开始菜单入口；其他同名入口和任务数据会保留，重新安装并打开插件后可继续管理。

只有看到 **“Codex Scheduler 已卸载，本插件的后台启动项与管理器入口已删除；本机任务数据保留。”** 才表示卸载成功。“按任意键继续”只是窗口等待关闭，并不代表成功。若提示缺少完整插件文件，安装或卸载尚未执行，请先完整解压后重试。

## 数据与权限

消息内容、发送时间、任务状态和结果摘要保存在本机。管理器仅监听本机地址并使用随机访问令牌。后台使用 Codex 桌面的现有登录，不要求复制账号凭证、Cookie 或 API Key。为连接桌面工具服务，本机仅登记桌面提供的管道地址、真实来源对话 ID 和登记时间；不保存账号令牌、历史调用 ID 或轮次 ID。启动器只保存必要的本地路径，不复制调用它的进程中的账号或 API 环境变量。令牌链接只用于打开本机管理器，请不要分享。

删除任务会移除本地任务内容、目标与结果；带创建去重编号的请求仅保留其 SHA-256 摘要，用于阻止迟到的创建重试恢复已删任务。

定时任务沿用所选对话的执行权限，并受 Codex 的权限和限制约束。后台不会代为批准交互请求；需要人工处理时，请回到原对话继续。
